# 統合版・iOSで実際にハマった点

- iOS/iPad はファイル名ごとに読み込み結果を覚える。そのため、配布ファイル名に版を入れる（同じ名前だと古い版が読み込まれ続けた）
- manifest の name に `pack.name`（翻訳キー）を使うと、読み込み先のフォルダ名が毎回 `pack.name` になり、古いキャッシュと混ざった。name には版入りの文字列を直接書く
- ワールドは追加したときの版に固定される。更新したら新しいワールドで試すか、パックを付け直す
- 読み込んだパックは上書きされず、版ごとに別のパックとして溜まる（自動で入れ替わるのはマーケットプレイス品だけ）。さらにワールドのフォルダ内 `behavior_packs`/`resource_packs` にもコピーが残り、設定のストレージからは消せない。ワールドの `world_*_pack_history.json` に一度使った版の記録が残り、ワールド編集の「利用可能」に古い版（中身なし）が出続ける（ファイルごと消せば消える）。テストは開発用フォルダ（テスト用 zip）で行う
- client_entity の format 1.10.0 では `animation_controllers` は使えない（`animations` と `scripts.animate` を使う）。使うと定義ごと捨てられ、村人が透明になった
- 自作の生き物に `minecraft:follow_range` が無いと、追いかけ・経路探索が16ブロックまでになる。遠い目的地に向かえず、見ている間その場で止まった（64を指定）
- `render_controllers` を空にしてはいけない。見えない物は `part_visibility` で全部隠す
- 立てる場所の判定では、雪の層・草花・苗木は「通れる」、葉っぱは「足場にしない」。そうしないと雪面で1段浮いたり、木の上に登ったりした
- エンティティの format_version が 1.21.0 のとき、`damage_sensor` の `"deals_damage": "no"`（文字列）は効かなかった（新しい形式用）。`false`（真偽値）で書く。効いていない間は、村人が殴られると1ダメージ、倉庫は赤く光って音が鳴り、目印は村人の攻撃で消えていた
- 村長の杖で叩いたダメージだけ、`damage_sensor`（`has_equipment` で杖を判定）と `entityHurt` の回復で打ち消している
- アイテム名は自前の辞書ではなく `ItemStack.localizationKey` を `{ translate }` で表示する（プレイヤーの言語で出る）
- 寝るモデルは向いている方と逆に頭が来る。ベッドの足側を向かせる
- 普通のチェストのふたをアドオンから開閉する方法は無い（プレイヤーが開けたときだけ）。そのため倉庫は専用のエンティティにした
- family に `inanimate` を入れたエンティティ（ボート・トロッコ扱い）は、プレイヤーが殴ると一撃で壊れた（damage_sensor でも防げない）。倉庫は入れず、体力を多めにして、壊れたら置き直す
- エンティティの `minecraft:is_collidable` は通り抜けは防げるが、プレイヤーの自動ジャンプでは乗れない（手前で止まる）。チェストのように乗れる当たり判定にはブロックを使う
- 生き物ごとに畑の踏み荒らしを止める設定は無い（mobGriefing は全体に効くので使わない）。村人の足元を見張って直している
- `getTopmostBlock` は、作物（当たり判定なし）の下の畑の土や、木の上の雪を返すことがある
- 見えないマーカーにも当たり判定が残る。`custom_hit_test` の当たり判定を地面の下に置き、チェストの上には置かない
- プレイヤーから離れたチャンクは止まる。村人は `getEntities` に出てこなくなる
- 動作確認はユーザーの実機（iPad）でしかできない。コンテンツログ（設定 → クリエイター）の `[error]` が一番の手がかり
